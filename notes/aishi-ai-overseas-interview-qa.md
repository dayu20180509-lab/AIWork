# 爱诗科技 · AI 出海应用开发工程师面试题（含参考答案）

> 面向 **PixVerse / 拍我AI** 类 AI 视频生成出海产品。岗位通常要求 **iOS 客户端 + 服务端/链路协作** 能力，偏应用落地而非纯算法。  
> 建议面试节奏：基础筛选 → iOS 深挖 → 服务与异步链路 → 出海与合规 → 系统设计。

---

## 一、岗位画像与考察目标

| 维度 | 考察重点 |
|------|----------|
| iOS | Swift 并发、媒体播放/导出、弱网与长任务 UX、IAP、App Store 审核与多区域发布 |
| 服务 | 异步任务编排、队列与幂等、对象存储/CDN、鉴权限流、多区域部署 |
| AI 应用 | 文生视频/图生视频请求链路、进度推送、失败重试与成本控制 |
| 出海 | GDPR/隐私、本地化、支付与税务、合规内容安全、跨时区运维 |

## 二、综合与产品理解（开场）

### Q1. 你如何理解「AI 出海应用开发工程师」和纯 iOS / 纯后端的区别？

**参考答案：**

- 不只写 UI 或 CRUD，而是负责 **端到端生成体验**：提交任务 → 排队/推理 → 进度反馈 → 成片下载/播放 → 分享/再编辑。
- 需要同时理解 **客户端长任务 UX**（后台、杀进程、弱网）和 **服务端异步架构**（队列、幂等、超时、成本）。
- 出海场景额外关注：多语言、多支付渠道、区域合规、CDN 就近、审核政策差异。
- 与算法同学的边界：应用侧关注 **API 契约、SLA、降级、可观测**；算法侧关注模型效果与推理吞吐。

### Q2. 以文生视频为例，描述从用户点击「生成」到看到成片的完整链路。

**参考答案（期望分层清晰）：**

1. **客户端**：校验登录/配额 → 组装 prompt、分辨率、时长、参考图 → 本地预检（敏感词可做轻量提示）→ 发起创建任务 API。  
2. **API 网关**：鉴权、限流、风控、计费预扣/配额检查。  
3. **任务服务**：落库 `task_id`（状态 `queued`）→ 投递消息队列 → 立即返回 `task_id`。  
4. **Worker/推理编排**：拉取任务 → 调推理集群 / 模型服务 → 中间态写进度（%）→ 产出视频写入对象存储。  
5. **通知**：WebSocket / SSE / APNs / 轮询刷新状态为 `succeeded`，返回 CDN URL。  
6. **客户端**：播放、缓存、导出相册、分享；失败则展示可重试原因与退款/退配额策略。

**追问加分点：** 幂等键、重复提交、用户杀 App 后如何恢复任务、部分成功（有预览无成片）怎么处理。

## 三、iOS 部分

### Q3. Swift 中 `async/await`、`Task`、`Actor` 分别解决什么问题？在视频生成页你会怎么用？

**参考答案：**

- `async/await`：用结构化并发表达异步 IO（网络、磁盘），避免回调地狱。  
- `Task`：创建并发工作单元；注意取消（页面消失时 `task.cancel()`）与优先级。  
- `Actor`：保护可变共享状态（如任务列表内存缓存、下载进度字典），避免数据竞争。  
- 实践：用一个 `GenerationSession` actor 管理当前任务状态；UI 用 `@MainActor` 更新；轮询/WebSocket 接收在后台 Task，合并到主线程刷新。

### Q4. App 被杀或进入后台后，进行中的生成任务如何保证用户回来还能看到结果？

**参考答案：**

- **真相源在服务端**：本地只缓存 `task_id` + 最近状态；冷启动用本地列表 + 批量查询任务状态。  
- 后台：`BGAppRefresh` / `BGProcessing` 能力有限，不能依赖客户端跑推理；用 **推送（Silent/Alert）** 或下次打开时同步。  
- 本地持久化：`UserDefaults`/`SwiftData`/`SQLite` 存任务摘要；大文件不进本地 DB。  
- 展示：首页「我的创作」以服务端为准，本地乐观更新需可回滚。

### Q5. 如何设计弱网下的生成与上传体验（含参考图上传）？

**参考答案：**

- 大图先压缩/转码（HEIC→JPEG），显示上传进度与可取消。  
- 分片上传或直传 OSS（预签名 URL），避免经业务服务器中转。  
- 断点续传；失败自动重试（指数退避 + 抖动）；区分可重试（超时）与不可重试（401、内容违规）。  
- 生成请求与媒体上传解耦：先拿 `asset_id`，再创建 generation task。  
- UX：明确「排队中 / 生成中 / 上传中」，避免用户重复点击；按钮防抖 + 幂等 token。

### Q6. iOS 上播放、缓存、导出短视频有哪些要点？

**参考答案：**

- 播放：`AVPlayer` + `AVPlayerViewController` 或自定义层；注意 Audio Session（与别的 App 混音）、HDR/SDR、旋转。  
- 缓存：HTTP 缓存或自建磁盘 LRU；CDN URL 带签名时注意过期刷新。  
- 导出相册：`PHPhotoLibrary` 权限文案与用途说明需符合审核；大文件导出放后台队列，完成后通知。  
- 内存：避免一次性读入整片 Data；用 `AVAssetExportSession` 做转码/裁剪。

### Q7. 海外 IAP（内购）与订阅，你怎么设计客户端与服务端对账？

**参考答案：**

- 客户端：StoreKit 2（`Transaction`、`Product`、`VerificationResult`）；处理挂起、换端、家庭共享。  
- **以服务端收据校验为准**（App Store Server API / 通知）；客户端成功仅作乐观 UI。  
- 订阅状态机：`active / grace / billing_retry / expired / refunded`；Webhook（ASSN V2）驱动权益变更。  
- 防丢单：启动时 `Transaction.currentEntitlements` + 服务端同步；本地未完成交易 finish 时机要正确。  
- 出海：多店（若有）、税务展示、恢复购买入口必做。

### Q8. App Store 出海常见拒审点有哪些？AI 生成类 App 还要注意什么？

**参考答案：**

- 常见：登录强制、权限用途不清、IAP 绕过、元数据与截图不符、崩溃/占位功能。  
- AI 生成：需 **内容安全与举报机制**、年龄分级、生成内容归属说明、是否使用第三方模型的披露。  
- 隐私：Privacy Nutrition Labels、ATT（若追踪）、账户删除能力（多地法规要求）。  
- 若含 UGC 视频：审核指南 1.2 安全、过滤与封禁流程。

### Q9. 如何做 iOS 性能与稳定性监控？生成页卡顿怎么排查？

**参考答案：**

- 工具：Instruments（Time Profiler、Allocations、Metal/GPU）、os_signpost、MetricKit、第三方（Sentry/Firebase Crashlytics）。  
- 卡顿：主线程是否做 JSON 大解析、图片解码、同步 IO；列表是否差量更新；视频缩略图是否过多同时解码。  
- 指标：启动耗时、冻帧、崩溃率、生成页转化漏斗（点击→成功提交→成功出片）。

### Q10. SwiftUI 与 UIKit 如何选型？列表大量「我的作品」怎么做？

**参考答案：**

- 新页面可用 SwiftUI；复杂播放器、自定义转场、成熟相册选择器可 UIKit 混编。  
- 大量作品：分页 + prefetch；缩略图异步；`LazyVGrid`/`UICollectionView`；cell 复用与取消过期图片请求（如以 `task_id` 为 token）。  
- 状态：单一数据源 + 单向更新，避免 SwiftUI 过度 redraw。

### Q11. 客户端如何实现生成进度：轮询 vs WebSocket vs 推送？

**参考答案：**

| 方式 | 适用 | 注意 |
|------|------|------|
| 轮询 | 实现简单、穿透性好 | 间隔退避；合并多任务批量 query |
| WebSocket/SSE | 进度实时、服务器可推状态 | 心跳、重连、鉴权过期、后台挂起 |
| APNs | App 不在前台 | 延迟与到达率；作补充非唯一 |

推荐：**前台 WS/SSE + 后台推送 + 冷启动轮询兜底**。

### Q12. 多语言与 RTL、时区在 iOS 侧怎么落地？

**参考答案：**

- `Localizable.xcstrings` / String Catalog；服务端错误码映射本地文案，避免直接展示英文 raw message。  
- 日期用 `RelativeDateTimeFormatter` / 用户时区；生成耗时预估用相对时间。  
- RTL：避免写死 leading 像素；图片箭头镜像策略要想清楚。  
- 文案长度：德/法语可能比中文长 30%+，按钮勿写死宽度。

## 四、服务端部分

### Q13. 设计「创建视频生成任务」API：你会怎么定义接口与状态机？

**参考答案：**

```http
POST /v1/generations
Idempotency-Key: <uuid>
{ "prompt": "...", "mode": "t2v", "duration": 5, "ratio": "16:9", "ref_assets": ["..."] }

→ 202 { "id": "gen_xxx", "status": "queued" }

GET /v1/generations/{id}
→ { "status": "running", "progress": 0.42, "eta_sec": 20 }

# 终态
status: queued | running | succeeded | failed | cancelled
```

- 状态机单向：`queued→running→succeeded|failed`，允许 `cancelled`（仅排队中或可中断点）。  
- 成功带 `outputs[].url`（短时签名或持久 CDN + 权限检查）。  
- 失败带稳定 `error_code`（`CONTENT_POLICY` / `TIMEOUT` / `CAPACITY` / `INTERNAL`）。

### Q14. 为什么生成任务必须幂等？如何实现？

**参考答案：**

- 弱网重试、客户端双击、网关重放会导致 **重复扣费与重复占 GPU**。  
- 用 `Idempotency-Key`（用户维度唯一）在 Redis/DB 做唯一约束；相同 key 返回首次任务。  
- Worker 侧消费用 `task_id` 去重；推理调用带业务 id，防止重复跑。

### Q15. 队列选型与优先级：免费用户 vs 会员，高峰如何削峰？

**参考答案：**

- 队列：Kafka / RabbitMQ / SQS / Redis Stream，按团队栈选择；关键是 **可见性超时、死信、重试次数**。  
- 多级队列或权重：会员高优先级；免费用户限流 + 更长 ETA。  
- 削峰：令牌桶准入；超过容量返回 `CAPACITY` 并给 ETA；弹性扩容 Worker；降级分辨率/时长。  
- 成本：按用户配额、并发上限（每用户 in-flight N）。

### Q16. 视频与封面存哪里？如何保证全球播放体验？

**参考答案：**

- 对象存储（S3/OSS/R2）+ **多区域 CDN**；源站按上传区就近。  
- 元数据在强一致存储（如 MySQL/PG）；内容文件最终一致即可。  
- URL：带过期签名防盗链；或 Cookie/Token 鉴权；热点短视频可公开缓存。  
- 生命周期：草稿 7 天、成片按会员等级保留；定期归档冷存储。

### Q17. 鉴权、风控与配额你会怎么做？

**参考答案：**

- 鉴权：Access Token（短）+ Refresh；设备指纹辅助；服务间 mTLS / 内网。  
- 配额：日生成次数、并发数、分辨率档位；Redis 原子扣减；预扣+确认（失败回滚）。  
- 风控：IP/设备速率；异常刷量；内容安全（文本+图像+视频抽帧）异步审核，违规置失败并记审计。  
- 出海：按地区合规开关（例如某些特效/模型不可用）。

### Q18. 如何设计可观测性，才能在「大面积排队变慢」时快速定位？

**参考答案：**

- 指标：队列深度、入队速率、推理 P50/P95、失败率按 `error_code`、GPU 利用率、CDN 4xx/5xx。  
- 链路追踪：`trace_id` 从客户端带到 Worker；日志结构化。  
- 告警：队列深度陡增、成功率跌破阈值、ETA 飙升。  
- 运营看板：分国家/套餐成功率，区分「模型慢」还是「上传/CDN」问题。

### Q19. 多区域部署：用户在美国、推理在某区，怎么架构？

**参考答案：**

- 就近接入（Global LB）；用户数据与任务元数据需明确 **home region** 或全局任务路由表。  
- 推理资源可能集中在有 GPU 的区域：任务跨区投递，结果回写用户区存储或直接上全球 CDN。  
- 延迟权衡：元数据同步 vs 跨区拉取媒体；合规数据驻留（欧盟数据不出境）要产品化配置。  
- Session：JWT 全球可验（公钥）或区域鉴权服务。

### Q20. 数据库表怎么设计（任务、资产、订单）？有哪些索引与坑？

**参考答案：**

- `users`、`assets`（上传原图）、`generations`（任务）、`generation_outputs`、`entitlements`/`orders`。  
- 高频查询：`generations(user_id, created_at DESC)`；`status` 单独查需组合索引或分表。  
- 坑：把大 JSON prompt 当列表字段全量扫；状态更新热点行；用 DB 当队列。  
- 账单与任务分库：财务对账与生成流量隔离。

### Q21. 服务端如何与模型推理服务解耦？

**参考答案：**

- 推理集群提供内部 gRPC/HTTP：`CreateInferJob` / `GetJob`；应用层不绑死某一模型版本。  
- 模型版本写入任务快照，保证可复现与客诉定位。  
- 超时与取消：应用层 watchdog；取消信号传到推理侧释放 GPU。  
- 灰度：按用户百分比路由到新模型；对比耗时与用户满意度（点赞/再编辑率）。

### Q22. 支付：Stripe / IAP / Google Play 并存时，权益中心如何统一？

**参考答案：**

- 抽象 `Entitlement`：`plan`, `source`, `expires_at`, `quota_bonus`。  
- 各渠道 Webhook 标准化进账；客户端只问「我有什么权益」不关心渠道细节。  
- 冲突：同账号多端订阅取最高权益或可叠加规则写清；退款回收权益要即时。  
- 发票与税务按渠道与国家处理，应用层少碰。

## 五、端云协同 / 系统设计题

### Q23. 系统设计：支持日均千万级生成请求的「AI 短视频生成」后端（45 分钟题）。

**参考答案框架：**

1. **接入层**：API Gateway + WAF + 限流；鉴权。  
2. **同步路径**：创建任务极薄，毫秒级返回。  
3. **异步路径**：分区队列 + Worker Pool + GPU 调度；优先队列。  
4. **存储**：元数据 DB + 对象存储 + CDN。  
5. **实时**：连接服务（WS）按 `user_id` 订阅 `task_id`。  
6. **弹性**：K8s HPA 基于队列深度；推理单独扩展。  
7. **降级**：关免费通道、降分辨率、只出图不出视频。  
8. **安全**：内容审核流水线并行，不阻塞入队但可阻塞对外分发。  
9. **成本**：按秒计 GPU、空闲回收、Spot 实例（需可打断重试）。

### Q24. 客户端开多个生成任务，服务端如何限制与展示 ETA？

**参考答案：**

- 限制：账户级 `max_inflight`；超出返回明确错误。  
- ETA：根据队列位置 × 近期任务均时 × 用户优先级估算；平滑避免跳动。  
- 客户端：任务卡片列表；完成用局部刷新；全局 Toast/推送可开关。

### Q25. 出现「用户已扣次但任务失败」怎么做闭环？

**参考答案：**

- 预扣配额 → 成功确认 / 失败回滚；或失败自动退次并发补偿券。  
- 对账任务：日终比对支付、配额流水、任务终态。  
- 客服工具：按 `task_id` 查全链路日志与退次按钮（鉴权审计）。

## 六、出海、合规与协作

### Q26. GDPR / 隐私合规对技术架构有哪些硬要求？

**参考答案：**

- 最小化采集；明确法律依据；同意与撤回。  
- 数据主体权利：导出、删除（账户删除级联任务与资产，或匿名化）。  
- 跨境传输机制；欧盟数据驻留可选。  
- Breach 通知流程；处理活动记录。  
- 技术：加密静态与传输、权限最小化、第三方 SDK 盘点（ATT/隐私标签）。

### Q27. 内容安全在端与云如何分工？

**参考答案：**

- 端：基础提示、本地敏感词（可绕过，仅 UX）。  
- 云：文本/图像审核；视频抽帧+音频；人审队列。  
- 策略：先审后发或边生成边审；违规不返回可分享 URL。  
- 用户举报 → 下架 → 模型/Prompt 样本回流（合规前提下）。

### Q28. 与算法、产品、运营跨角色协作时，你如何写好 API 与发布？

**参考答案：**

- API 契约优先（OpenAPI）；字段兼容：只增不改语义；版本 `/v1`。  
- Feature flag：按国家、百分比放量。  
- 发布：客户端可旧版兼容新字段；服务端兼容旧客户端缺字段默认值。  
- 事故：回滚模型版本与开关，而不是强依赖紧急发版 App。

## 七、编码题（可选现场）

### Q29. iOS：实现一个带取消的任务状态轮询器（思路即可）。

**参考答案要点：**

- `actor Poller` 持有 `Task`；`start(id:)` 循环 `try await api.status` + `Task.sleep`；检查 `Task.isCancelled`。  
- 退避：1s→2s→5s 上限；终态结束并回调 `@MainActor`。  
- 不要用 Timer + 闭包强引用循环引用。

### Q30. 服务端：用伪代码写「幂等创建任务 + 投递队列」。

**参考答案要点：**

```text
fn create(user, body, idem_key):
  if existing = db.find(user, idem_key): return existing
  tx:
    row = db.insert(generation queued)
    redis.set(idem_key → row.id, nx, ttl)
  queue.publish(row.id)
  return row
```

冲突时 catch unique violation 再查一次返回。

## 八、行为面与项目深挖（简表）

| 问题 | 期望听到 |
|------|----------|
| 讲一个你做过的长耗时任务产品 | 状态机、失败补偿、UX |
