## 二、iOS 深挖（紧扣简历项目）

### R3. 拼多多冷启动从 1.2s 到 1s 以内：四件事里，哪一件贡献最大？你怎么归因？

**简历锚点：** 启动任务分级、load 治理、Binary Reorder、首屏加载  

**参考答案（期望）：**

- 用数据说话：优化前后 Instruments / MetricKit / 分位数（P50/P90），不能只报平均值。  
- 能解释 Binary Reorder：启动路径符号顺序 → 提升页命中、减缺页；以及 **如何采集 order 文件、如何防回退**。  
- 能说明 load/+load、静态初始化的代价与治理手段（分类、调用下沉）。  
- 认清：1.2→1.0 在亿级 App 上很难，需说明机型/网络/版本对比条件。

**追问：** 若只能做一件事给 PixVerse 冷启动，你会先做哪件？为什么？

### R4. Binary Reorder 和「启动任务分级」冲突过吗？如何做取舍？

**简历锚点：** 同上  

**参考答案（期望）：**

- 重排优化的是 **同一次启动内的指令局部性**；任务分级优化的是 **该不该在启动同步跑**。  
- 先砍同步任务，再对剩余关键路径做重排，收益通常更稳。  
- 工程风险：重排与动态库/热修/bitcode/链路选项的兼容；CI 如何门禁 order 文件过期。

### R5. 偏好组「页面启动 +30%、包体积 -20%」——口径是什么？你个人做了哪些？

**简历锚点：** 拼多多偏好组 Owner；日志分析系统  

**参考答案（期望）：**

- 定义：页面启动是从点击到首屏可交互，还是到数据就绪？样本机型与版本。  
- 包体积：资源下沉、组件按需、无用代码/资源剔除、是否含动态库。  
- 「端内通用日志分析系统」：采集字段、采样、隐私、如何定位卡顿/接口慢——能画清链路。

### R6. 得物商详「组件化拆分 + 质量门禁」：模块边界怎么划？故障率怎么降？

**简历锚点：** 商详架构治理；代码评审与门禁  

**参考答案（期望）：**

- 边界按业务能力（头图、价格、SKU、评价、推荐）而非按人。  
- 门禁：Lint、单测/快照、包大小、启动/关键路径回归、CR 规则。  
- 故障：灰度、配置开关、降级（推荐挂了不影响下单）、oncall 复盘。  
- **迁移到爱诗：** 生成页、作品库、会员支付、播放器应如何拆模块。

### R7. 你带 6 人小组时，自己还有多少时间写核心代码？如何保证「架构师」不是纯管理？

**简历锚点：** 商详组组长  

**参考答案（期望）：**

- 给出可验证比例（如 50% coding / 关键路径亲自做）。  
- 举例：自己啃过的疑难（渲染、内存、跨端坑）。  
- 爱诗小团队更吃个人产出——候选人需表态愿意 hands-on。

### R8. Swift「熟练」、OC「精通」——近年 Swift 并发（async/await、Actor）用在哪个真实模块？

**简历锚点：** 技术栈声明  

**参考答案（期望）：**

- 具体模块 + 取消、隔离、主线程刷新方式。  
- 若仍以 OC/回调为主：承认并说明迁移计划，不装精通。  
- **缺口探测：** SwiftUI、StoreKit 2、Observation——用过没有。

### R9. 企鹅 FM「IP 竞速」如何实现？如何证明不是 DNS 劫持误报？缓冲 -30% 怎么测？

**简历锚点：** 腾讯企鹅 FM；音频播放成功率；首/二次缓冲 -30%  

**参考答案（期望）：**

- 多线路/多 IP 并发探测或串行竞速；选 RTT/首包最优；失败切换。  
- 王卡/运营商劫持：HTTPS、IP 直连、证书校验、监控域名 vs IP 差异。  
- 指标：首缓冲=点播到出声；二次缓冲=卡顿再缓冲；A/B 与分网络类型。

**迁移题：** 这对「全球 CDN 拉生成视频」有什么可复用？签名 URL 过期、择路、播放失败重试如何设计？

### R10. 拼多多「视频组件中间层」负责什么？和业务播放器怎么分层？

**简历锚点：** 组件组 Owner；视频组件中间层  

**参考答案（期望）：**

- 中间层：播放器封装、预加载、复用池、统一埋点/错误码、生命周期。  
- 业务只关心「播哪个 URL / 封面 / 自动播策略」。  
- **迁移：** AI 成片播放、作品列表预载、导出相册——中间层要暴露哪些接口。

### R11. Shopee 横向支持 RN、推动 RN2Web：边界在哪？Native 必须保留什么？

**简历锚点：** Shopee Banking 专家；RN2Web；跨端组件  

**参考答案（期望）：**

- 能讲清 RN 与 Web 容器差异：启动性能、手势、导航、原生能力（相机、支付、推送）。  
- RN2Web 目标（迭代速度/降包/统一栈）与代价（体验、离线、桥）。  
- 版本兼容：0.7x 升级坑（若能具体到新架构/Fabric 更好）。  
- **红旗：** 把跨端说成「不需要懂 Native」。

## 三、从简历经验 → AI 视频生成场景（迁移题）

### R12. 电商「商详秒开」和 AI「点生成等几十秒出片」，体验设计差异是什么？你会怎么做生成页？

**简历锚点：** 商详体验优化 vs 生成长任务  

**参考答案（期望）：**

- 复用其启动/首屏经验到：**App 启动后尽快恢复「我的任务」列表**。

### R13. 用你在偏好组/商详的「日志分析」思路，设计生成任务的端到端排查字段。

**参考答案（期望）：**

- `task_id` / `trace_id` / 用户与地区 / 机型 / 网络 / 上传耗时 / 排队时长 / 推理耗时 / 错误码 / 模型版本。  
- 端：提交点击、进后台、杀进程重进、播放失败。  
- 能说明采样与隐私（出海 GDPR）。

### R14. 得物「AI 开发四件套」和「AI 视频产品」不是一回事——你会如何把工程化能力迁到生成产品？

**简历锚点：** rules/skills/MCP/commands；Plugin；OpenSpec；防代码膨胀  

**参考答案（期望）：**

- 工程化可迁：契约（OpenAPI）、评审门禁、知识库（错误码/runbook）、成本（Token≈GPU 秒）。  
- 产品侧新增：内容安全、配额、模型灰度、用户可感知质量，而非只优化程序员效率。  
- 诚实：没有做过 DiT/推理调度也没关系，但要有清晰学习与协作边界。

## 四、服务端加压（简历薄弱区，必问）

> 目的：判断能否胜任岗位「服务」部分；不会可以不会，但要有清晰模型与学习路径。

### R15. 设计 `POST /v1/generations`：从你做过的「组件接入/跨端契约」经验出发，你会要求后端提供哪些字段与错误码？

**参考答案（期望）：**

- 立即返回 `task_id` + `status=queued`；`Idempotency-Key`。  
- 状态机：`queued|running|succeeded|failed|cancelled`。  
- 错误码：`CONTENT_POLICY` / `QUOTA_EXCEEDED` / `CAPACITY` / `TIMEOUT` —— 端上不同 UX。  
- 进度：`progress` / `eta_sec`；成功：`outputs[].url`（签名与过期）。

### R16. 弱网会重复点击「生成」——结合你做质量治理的经验，端 + 云如何一起做幂等？

**参考答案（期望）：**

- 端：按钮状态机、本地 dedupe token、以服务端 task 列表为准。  
- 云：幂等键唯一约束；重复请求返回同一任务。  
- 计费：预扣 + 失败回滚；防止双扣。

### R17. 会员高优先级、免费用户排队：若你来写「客户端展示的 ETA」，需要服务端给什么？只靠本地能算吗？

**参考答案（期望）：**

- 需要：队列位置或服务端 ETA、优先级档位、近期均时。  
- 本地无法准确算全球队列；最多做平滑展示。  
- 高峰降级文案与入口（降分辨率）如何配合配置下发。

### R18. 成片在 OSS + CDN：结合企鹅 FM 播放与电商图片经验，签名 URL 过期了客户端怎么做？

**参考答案（期望）：**

- 播放 403 时刷新 meta 拿新 URL；避免缓存过期签名。  
- 预加载与列表缩略图策略；防盗链与热点缓存。  
- 与 IP 竞速类思路结合：多线路失败切换（若有多 CDN）。

### R19. IAP / 订阅对账你做过吗？若没有，基于商详「成交确定性」经验，你认为权益中心应如何设计？

**参考答案（期望）：**

- 承认缺口则给方案：StoreKit 2 + 服务端校验 + ASSN；权益状态机。  
- 与订单类似：客户端乐观、服务端真相；掉单恢复、退款回收。  
- 多渠道（Stripe/IAP）统一 `Entitlement`。

### R20. 多区域：用户在美国、GPU 在另一区——你从 Shopee 出海经验里能迁移什么？还缺什么？

**参考答案（期望）：**

- 可迁移：多国家包、延迟体感、本地化、合规意识。  
- 缺口：数据驻留、跨境传输、推理调度——需明确承认并补齐概念（home region、任务路由、CDN）。
